# Claude Usage Meter

A tiny desk display that shows your **live Claude usage**: the 5‑hour session limit and the
weekly limit, each with a progress bar and a countdown to reset. Built on a ~$15 ESP8266
"SmallTV"-style 240×240 display, fed by Claude Code's status line over WiFi.

## Features

- **Live usage** for the 5‑hour and 7‑day windows, straight from Claude Code — no API keys,
  no scraping, no credentials leave your Mac.
- **Countdowns** that keep ticking on the device (own NTP clock), even when the Mac is asleep.
- **Colour-coded bars**: orange → amber above 80 % → red above 95 %.
- **Survives power loss**: last numbers are kept in flash and shown immediately on boot.
- **Stale indicator**: red dot when no fresh data for 15 min; grey dot before the first update.
- **Idle screen**: animated pixel-art scene after 10 min without changes; wakes on update.
- **Wireless firmware updates** (ArduinoOTA) after the first USB flash.
- **Token-protected** HTTP endpoint on the device.

## How it works

```
 Mac                                                         Display (ESP8266)
 Claude Code ─stdin─▶ statusline.sh ─▶ latest.json            ┌──────────────────┐
                           │ on change                        │ POST /usage      │
                           └──────────▶ push.sh ──HTTP/WiFi──▶│  ├─ save (flash) │
 launchd (every 60 s) ───────────────▶ push.sh ──────────────▶│  └─ draw         │
                                                              └──────────────────┘
```

Claude Code passes `rate_limits.five_hour` and `rate_limits.seven_day` (percent used +
reset time) to its status line command (see "Status line" in the Claude Code docs). The bridge records them and POSTs them to the display. A LaunchAgent re-sends the
latest numbers every minute so a freshly powered display fills in quickly.
Full details: **[docs/architecture.md](docs/architecture.md)**.

## Requirements

- An ESP8266 + ST7789 240×240 display board (GeekMagic SmallTV-style; see
  [docs/hardware.md](docs/hardware.md) for pins and other boards)
- macOS with Claude Code signed in with a
  Claude subscription (Pro / Max / Team — rate limits are only reported for subscriptions)
- `jq` and `curl` (`brew install jq`), Python 3 for PlatformIO
- Mac and display on the same 2.4 GHz WiFi network

## Quick start

### 1. Back up the stock firmware (recommended)

```sh
pip install esptool
esptool --port /dev/cu.usbserial-* read-flash 0 ALL stock-firmware-backup.bin
```

See [docs/hardware.md](docs/hardware.md#backup--restore) for verifying and restoring.

### 2. Configure and flash the firmware

```sh
git clone https://github.com/AlexVanchov/claude-usage-meter.git
cd claude-usage-meter
python3 -m venv .venv && .venv/bin/pip install -r tools/requirements.txt

cp firmware/src/secrets.example.h firmware/src/secrets.h
# edit secrets.h: WIFI_SSID, WIFI_PASS, METER_TOKEN (openssl rand -hex 12), METER_TZ

cd firmware
../.venv/bin/pio run -t upload --upload-port /dev/cu.usbserial-XXXX   # first time: USB
```

The display shows a boot screen, joins WiFi and announces itself as `claude-meter.local`.

### 3. Install the Mac bridge

```sh
bridge/install.sh --configure-claude
```

This creates `bridge/meter.env` (token copied from `secrets.h`), installs the LaunchAgent and
adds the status line to your Claude Code settings (backing them up first; respects
`CLAUDE_CONFIG_DIR`). Leave out `--configure-claude` to get the settings snippet printed
instead. Send any message in Claude Code and the display updates.

## Updating the firmware over WiFi

```sh
cd firmware
METER_TOKEN=<your token> ../.venv/bin/pio run -e ota -t upload
```

## Configuration

| Where | Setting | Default |
|---|---|---|
| `firmware/src/secrets.h` | `WIFI_SSID`, `WIFI_PASS`, `METER_TOKEN`, `METER_TZ` | — / UTC |
| `firmware/src/config.h` | hostname, backlight pin/level, rotation | `claude-meter`, 80 % |
| `firmware/src/config.h` | `STALE_AFTER_MIN`, `IDLE_AFTER_MIN` | 15, 10 |
| `bridge/meter.env` | `CLAUDE_METER_HOST`, `CLAUDE_METER_TOKEN` | `claude-meter.local` |

Fonts and pixel art are generated by `tools/gen_assets.py` (edit the sprite grids there,
then run `.venv/bin/python tools/gen_assets.py`). The design is described in
[docs/display.md](docs/display.md).

## Device API

| Method | Path | Description |
|---|---|---|
| `GET` | `/` | Status page |
| `GET` | `/usage` | Current state as JSON |
| `POST` | `/usage` | Update usage (requires `X-Meter-Token`) |
| `POST` | `/wake` | Leave the idle screen |

```sh
curl http://claude-meter.local/usage
```

Request format: [docs/architecture.md](docs/architecture.md#the-request).

## Troubleshooting

| Symptom | Check |
|---|---|
| Status line shows only the model name | You're not signed in with a subscription (`/status` in Claude Code). |
| Status line shows %, display doesn't change | `curl http://claude-meter.local/usage`; same WiFi? `tail ~/Library/Logs/claude-meter-push.log` |
| `{"ok":false,"error":"bad token"}` | `CLAUDE_METER_TOKEN` in `bridge/meter.env` ≠ `METER_TOKEN` in `secrets.h` |
| Display shows `--%` after power-up | Normal until the first update (≤ 60 s while the Mac is on). |
| Red dot in header | No fresh numbers for 15 min — Claude Code idle or Mac asleep/away. |
| Blank/dark screen on another board | Pins or backlight polarity differ — see [docs/hardware.md](docs/hardware.md). |

Serial log (115200 baud) prints WiFi, updates and heap stats:
`.venv/bin/pio device monitor -d firmware`.

## Uninstall

```sh
bridge/uninstall.sh        # removes LaunchAgent, status line entry and cached state
```

Restore the stock firmware with your backup (see [docs/hardware.md](docs/hardware.md#backup--restore)).

## Project layout

```
firmware/                PlatformIO project (Arduino core, TFT_eSPI, ArduinoJson)
  platformio.ini         board, pins, USB + OTA upload environments
  src/main.cpp           WiFi, NTP, HTTP API, persistence, OTA
  src/ui.cpp, ui.h       rendering: header, cards, animated footer, idle scene
  src/config.h           hardware + behaviour settings
  src/secrets.example.h  template for secrets.h (git-ignored)
  src/gen_fonts.h        generated anti-aliased fonts (do not edit)
  src/gen_sprites.h      generated pixel art (do not edit)
bridge/                  Mac side
  claude-meter-statusline.sh   Claude Code statusLine command
  claude-meter-push.sh         sends latest numbers to the display
  com.claude-meter.push.plist.template   LaunchAgent (every 60 s)
  install.sh, uninstall.sh
tools/
  gen_assets.py          font + sprite generator
  fonts/                 Inter, JetBrains Mono (SIL OFL 1.1)
docs/                    architecture, hardware, display design, images
```
